## V3.3 Security Additions

### 1. Rate Limiting

**Purpose:** Prevent abuse and DoS.

**Design:**
```python
class RateLimiter:
    """In-memory sliding window rate limiter."""

    def __init__(self, max_requests: int, window_seconds: int):
        self.max_requests = max_requests
        self.window_seconds = window_seconds
        self.requests: dict[str, list[float]] = {}

    def is_allowed(self, key: str) -> bool:
        """Check if request is within rate limit."""
        now = time.time()
        window_start = now - self.window_seconds
        self.requests[key] = [t for t in self.requests[key] if t > window_start]
        if len(self.requests[key]) >= self.max_requests:
            return False
        self.requests[key].append(now)
        return True
```

**Configuration:**
```ini
RATE_LIMIT_CHAT=10/minute
RATE_LIMIT_IMPORT=5/minute
RATE_LIMIT_SEARCH=30/minute
RATE_LIMIT_DEFAULT=60/minute
```

**Endpoints to protect:**
- `POST /chat` — 10/minute (provider cost)
- `POST /import/*` — 5/minute (resource intensive)
- `POST /search` — 30/minute
- `POST /memories` — 20/minute
- Default — 60/minute

### 2. Request Size Limits

**Purpose:** Prevent memory exhaustion.

**Design:**
```python
# FastAPI middleware
MAX_REQUEST_BODY = 10 * 1024 * 1024  # 10MB
MAX_UPLOAD_SIZE = 50 * 1024 * 1024   # 50MB for imports
```

**Enforcement:**
- All POST/PUT/PATCH endpoints: 10MB body limit
- Import endpoints: 50MB upload limit
- File validation before processing

### 4. Indirect Prompt Injection

**Purpose:** Prevent imported content from influencing system behavior.

**Defense layers:**
1. System prompt explicitly marks memories as DATA
2. Imported content wrapped in quotation marks
3. Conversation content cannot escape DATA section
4. Memory extraction uses separate prompt from chat

**Additional V3.3 measures:**
- Content length limits on imported messages
- Sanitization of imported content (remove control characters)
- Validation that imported content doesn't contain system prompt patterns

### 5. Backup Security

**Purpose:** Protect backup files from unauthorized access.

**Design:**
- Backups stored in `data/backups/` (excluded from git)
- Backup files named with timestamp and integrity hash
- Restore requires explicit confirmation
- Backup listing shows metadata only, not content

### 6. CORS Hardening

**Purpose:** Restrict cross-origin requests.

**Configuration:**
```ini
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
CORS_ALLOW_CREDENTIALS=true
CORS_ALLOW_METHODS=GET,POST,PATCH,DELETE
CORS_ALLOW_HEADERS=Content-Type,Authorization
```

### 7. Content Security Policy

**Purpose:** Prevent XSS and code injection.

**Headers:**
```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data:;
  connect-src 'self' http://localhost:8000;
```
