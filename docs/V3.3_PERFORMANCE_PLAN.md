## Performance Improvements

### 1. SQLite FTS5 Full-Text Search

**Problem:** ILIKE `%query%` scans entire table, O(n) per search.

**Solution:** FTS5 virtual table with inverted index.

**Impact:**
- Search latency: O(n) → O(log n)
- Storage: +10-20% for index
- Write performance: Minimal impact (index updated automatically)

**Implementation:**
```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(
    content, sender, language,
    content=messages,
    content_rowid=id
);

CREATE VIRTUAL TABLE memories_fts USING fts5(
    content, memory_type,
    content=memories,
    content_rowid=id
);
```

### 2. Composite Indexes

**Problem:** Single-column indexes don't cover multi-column queries.

**Additions:**
```sql
-- Messages hot path
CREATE INDEX ix_messages_conversation_timestamp
    ON messages(conversation_id, timestamp);

-- Memories hot path
CREATE INDEX ix_memories_person_status
    ON memories(person_id, status);

-- Memory relationships
CREATE INDEX ix_memory_relationships_from
    ON memory_relationships(from_memory_id);
CREATE INDEX ix_memory_relationships_to
    ON memory_relationships(to_memory_id);
```

**Expected impact:**
- Message list queries: 30-50% faster
- Memory list queries: 20-40% faster
- Conversation stats: 10-20% faster

### 3. Cursor Pagination

**Problem:** Offset-based pagination degrades with large offsets.

**Solution:** Cursor-based pagination using message ID.

**API change:**
```json
// Before
GET /messages?limit=200&offset=200

// After
GET /messages?limit=200&cursor=400
```

**Impact:**
- Large conversation loading: O(1) instead of O(offset)
- No performance degradation with conversation size

### 6. Query Optimization

**Problem:** `PersonRepository.get_by_normalized_name` loads all persons.

**Solution:** Database-level JSON search or dedicated aliases table.

```python
# Option 1: Database JSON search (SQLite 3.38+)
def get_by_normalized_name(self, name: str) -> Optional[Person]:
    normalized = self.normalize(name)
    return self.session.query(Person).filter(
        or_(
            func.lower(Person.name) == normalized,
            Person.aliases.contains(normalized)
        )
    ).first()

# Option 2: Dedicated aliases table (better performance)
# CREATE TABLE person_aliases (
#     person_id INTEGER REFERENCES persons(id),
#     alias TEXT,
#     normalized TEXT
# );
```

### 7. Frontend Virtualization

**Problem:** All messages rendered in DOM simultaneously.

**Solution:** `react-window` FixedSizeList for message rendering.

**Impact:**
- DOM nodes: O(n) → O(visible + buffer)
- Memory usage: 50-80% reduction for large conversations
- Initial render: 60-70% faster

### Monitoring

```python
# Request timing middleware
@app.middleware("http")
async def timing_middleware(request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    duration = time.perf_counter() - start
    metrics.record("http_request_duration", duration, {
        "method": request.method,
        "path": request.url.path,
        "status": response.status_code,
    })
    return response
```
