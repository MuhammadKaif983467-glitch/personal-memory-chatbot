### Backend Changes

**FTS5 Integration**
```python
# New repository method
class MessageRepository:
    def search_fts(self, query: str, *, limit: int = 50) -> list[Message]:
        """Full-text search using SQLite FTS5."""
        sql = text("""
            SELECT m.* FROM messages m
            JOIN messages_fts fts ON m.id = fts.rowid
            WHERE messages_fts MATCH :query
            ORDER BY rank
            LIMIT :limit
        """)
        return session.execute(sql, {"query": query, "limit": limit}).scalars().all()
```

## Migration Strategy

All V3.3 changes are **additive**:
- New tables (FTS5 virtual tables, memory_relationships, conversation_summaries)
- New indexes
- New columns (nullable, with defaults)
- ON DELETE CASCADE added via migration

No existing columns or tables are modified or removed.

## Performance Considerations

| Change | Impact | Mitigation |
|--------|--------|------------|
| FTS5 tables | +10-20% storage | Acceptable for search speed |
| Composite indexes | +5% storage, slower writes | Acceptable for read-heavy workload |
| CASCADE deletes | Slightly slower deletes | Use manual cleanup for bulk operations |
| Virtual scrolling | Zero DOM overhead for large lists | Only visible messages in DOM |
| Backup API | Brief lock during backup | Use `conn.backup()` (non-blocking) |

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| FTS5 compatibility | Low | High | FTS5 built into SQLite 3.9+ (widely available) |
| Migration failure on large DB | Medium | High | Batch migration, test with 10k+ messages |
| Virtual scroll regression | Medium | Medium | Extensive E2E testing |
| Backup corruption | Low | High | Integrity verification after backup |
| Rate limiting false positives | Medium | Low | Configurable thresholds |
