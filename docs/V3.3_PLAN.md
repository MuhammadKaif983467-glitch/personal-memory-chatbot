## Feature Priorities

### FOUNDATIONAL

**Database hardening** — Add ON DELETE CASCADE, composite indexes, FTS5 for search. Prevents data corruption and enables all other features.

**Dead code cleanup** — Remove 14 unused frontend files, orphaned chat subsystem, legacy prompts. Reduces maintenance burden.

### HIGH PRIORITY

**Advanced retrieval** — Reranking, query expansion, temporal relevance. Directly improves response quality.

**Conversation summarization** — Compress long conversations for context windows. Enables 100k+ message support.

**Backup/recovery** — SQLite backup API, scheduled backups, restore validation. Critical for production use.

**Browser E2E** — Playwright tests for critical flows. Prevents regressions.

### MEDIUM PRIORITY

**Memory engine v2** — Semantic grouping, importance decay, contradiction detection. Improves memory quality.

**Style engine v2** — Deeper linguistic modeling, language mixing, phrase frequency. Better style matching.

**Observability** — Structured logging, metrics, provider latency tracking. Essential for production debugging.

**Search upgrade** — SQLite FTS5 for full-text search. Replaces slow ILIKE queries.

### OPTIONAL

**Import v2** — Resumable import, progress streaming, malformed-record recovery. Nice-to-have for large imports.

**Export v2** — CSV export, streaming export. Low priority.

**Response quality** — Hallucination detection, grounding validation. Complex, provider-dependent.

### DEFER

**Voice** — Full STT/TTS integration requires external providers, microphone permissions, streaming. Too complex for V3.3.

**Multi-user** — Authentication, authorization, user management. Fundamental architecture change.

**Evaluation benchmarks** — Requires curated datasets, ground truth, scoring pipeline. Independent project.

## Database Changes (V3.3)

### Additions
- `memory_relationships` table (memory_id, related_memory_id, relationship_type)
- `conversation_summaries` table (conversation_id, summary, created_at)
- FTS5 virtual tables for messages and memories
- Composite indexes on hot query paths

### Modifications
- Add ON DELETE CASCADE to all foreign keys
- Add `archived_at` timestamp to projects for soft-delete
- Add `import_batch_id` to messages for resumable import tracking

### No Changes
- V3.2.0 data remains fully compatible
- No column renames or drops
- No table renames

## API Changes (V3.3)

### New Endpoints
- `POST /backup/create` — Create database backup
- `GET /backup/list` — List available backups
- `POST /backup/restore` — Restore from backup
- `GET /conversations/{id}/summary` — Get conversation summary
- `POST /memories/relationships` — Create memory relationship
- `GET /memories/{id}/relationships` — Get memory relationships

### Modified Endpoints
- `GET /messages` — Support cursor pagination
- `POST /search` — Use FTS5 for faster search
- `GET /export/messages` — Support CSV format, streaming
